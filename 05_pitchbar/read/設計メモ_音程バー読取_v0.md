# 設計メモ 音程バー読取 v0（E4・お手本メロディの復元）

作成 2026-10-08／担当 Claude（研究実装）／本筋との関係 **D2（検出精度の向上）の「入力を変える」軸**＝お手本音程との差を学習器の入力に加えるための前処理。学習は行わない。
※ 本メモは「試作で確かめた事実」を優先して書く。最初の仮説と違った点は ★ で示す。

## 0. 目的と出力

- 入力：スマホで撮った DAM 精密採点（WAO 画面）の録画 `G:\研究アーカイブ\ビデオ素材\<S>\<video>.mp4`（4K・59fps）。
- 出力：`out\<video>_ref.csv`＝10ms 刻みの基準メロディ列。列＝`time_sec`（動画 pts 秒）・`audio_time_sec`（＝time_sec＋同期表 offset_sec・録音 WAV の時刻）・`ref_midi`（半音に丸めた MIDI 番号）・`ref_midi_raw`・`conf`（ページ内フレームのうち、その列でバーが読めた割合）・`n_votes`・`page`・`page_m0`（そのページの音域オフセット）・`ref_y_px`・`pyin_midi`（検証用）。
- 期限：10/31 までに 28 曲（9/24 セッション）で出力が出ること。

## 2. 読み方（scripts/read_pitchbar.py）

### 2.1 ROI（画面位置合わせ）
帯プローブ（`dataset/band_probe_v2_<S>.csv`：xL, yL, w, angle_deg）を流用。x＝xL〜xL+1.5w、y＝yL−0.21w〜yL−5、回転＝wincrop と同じ `rotate(−angle)`。ffmpeg で切り出し `-fps_mode passthrough` → 横 1/2・縦原寸の rawvideo を Python に流す。フレーム番号 i ↔ 時刻は元動画の pts 表 `dataset/pts/<video>.csv`（既存 `Cfg.ensure_src_pts`）。処理速度＝約 30ms/フレーム（cv2.inRange）＋復号＝**1 曲 13〜15 分（5 並列時 25 分）**。

### 2.2 縦軸（音高）＝段階1 read
列ごとに「内側＋縁」の対で読む（背景の明るさに依存しない。★塗りの連続ランで読む最初の案は明るい背景で破綻した）：
- 塗りバー：淡い白（V≥90・S≤110・金でない）の縦ランが 40〜56px で、上下 4px 以内に金（H10〜40・S≥140・V≥80）。
- 中抜きバー：黒（V<70）の縦ランが 41〜50px で、上下 4px 以内に白線（V≥150・S≤100）。譜線の隙間（35〜37px）は長さの下限で落ちる。
- 赤丸（歌った音程）は先に除外。横に同じ中心（±3px）が 16 列（原寸 32px）以上続く区間だけ採用＝楕円・技法マーク・火花を落とす。
- 保存＝フレームごとの「バー区間（x0, x1, 中心 y）」とカーソル x（`out/<video>_frames.npz`）。**ページ分割・時刻付け・換算は段階2で何度でもやり直せる**（復号は 1 回）。
- 譜線の行＝行プロファイル（全フレーム中央値）に、事前値（0.01688×帯幅）±8% の間隔で 12 本の櫛を当てる。左 1/4 と右 1/4 の差で**傾き**を補正。

### 2.3 横軸（時間）＝段階2 eval
- カーソル x：右 +6 列より 15 以上明るく左 −6 列より極端に暗くない行の数が高さの 50% 以上の列。ベゼル段差・ROI 端は除外。静止した候補（0.5 秒で幅 ≤4px）は背景の縦エッジ＝捨てる。
- **ランプ抽出**：検出列を先頭から RANSAC（直線 x=v·t+b・v 150〜450・内点 ±6px・10 点以上・1 秒以上）で貪欲に切り出す。1 ランプ＝1 ページ。ページ内でテンポが変わって折れる場合は 2 本に分ける。
- **ページ境界**＝次のランプの t0（カーソルが x=0 を通る時刻）。前ページの予測終了 t0+x_end/v（x_end＝隣接ランプから求める「切替時のカーソル x」≈1,640px）と次の t0 の隙間が典型ページ長の半分以上なら、間はカーソルが読めなかったページ＝枚数を割り当てて等分に補間（`timing=interp`／`interp_multi`）。
- 列 x の時刻＝`t0 + x/v`。ページ内の全フレームが同じ列に投票するので、演出で一時的に隠れても他のフレームが埋める。

### 2.4 統合と換算
ページ × 列 × 中心 y（2px 刻み）の投票表 → 列ごとに最多の y・票数（conf＝票数/ページ内フレーム数、下限 5%）→ 10ms 格子。
y → 半音：`midi = m0_p − 2 × (y − y_top)/spacing`。**m0_p（ページの最上線の MIDI）は画面から読めないので pYIN との一致数最大で決める（整数・ページごと・比較 50 コマ以上のページ）。** k（1 本=1 or 2 半音）と表示遅れ dt（±0.6 秒）は曲全体で 1 組（ページ別オフセットを許した一致数の合計で選ぶ）。5 曲とも k=2・dt=−0.08〜−0.10 秒（画面がわずかに先行＝録音との同期の誤差を含む）。

## 3. 自己検証（pYIN との一致率）
- 対象：`ref` があり、pYIN が有声（voiced かつ conf≥0.5）の 10ms コマ。
- 指標：**agree50**（±50 cent）・agree100（±1 半音）・agree50_octave_free・coverage（有声コマのうち ref があった割合）・**note_agree50**（ref が一定の音符ごとに、両端 50ms を除いた内側の pYIN 中央値が ±50 cent）・30 秒ブロック別。
- 解釈：一致率は「読取の正しさ」×「歌の正確さ」の積＝読取精度の**下限**。DAM 自身の「音程」（radarChartPitch・9/24 は 81〜84）が歌の正確さの外部参照になる（許容幅は非公開）。
- m0_p を pYIN で決める以上、ページ内の相対音程・時刻付け・ページ分割の正しさを検証していることになる（オフセット 1 個で全音符が揃うかどうか）。

## 4. 既知の限界（v0）
1. 絶対音高（m0_p）は画面から読めない＝pYIN で合わせる（ページごと）。歌がページ全体で半音ずれていれば ref も半音ずれる。比較が 50 コマ未満のページ（間奏・歌わなかった）は曲の代表値を使う＝信頼できない（`page_m0` 列で判別可）。
2. カーソルが読めないページ（明るい背景・5 曲平均 1/4）は補間＝一致率が 25〜31%（カーソルあり 40%）。
3. 32px（横 1/2 で 16 列）未満の短いバーは落とす。歌った音程の白楕円がまれにバーに化ける（短い跳び）。
4. Ai 機の画面は未対応。
