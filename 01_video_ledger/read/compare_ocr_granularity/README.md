# 切り出し粒度を変えた数字読み取りの比較 2026-10-29

録画の加点回数表示（画面下部の加点表示領域にある技法別の回数）を数字として読み取る工程で、
**入力の切り出し粒度**を変えると読み取りの正しさと処理時間がどう動くかを測る実験の一式。
2026-10-18 の比較（`ocr_compare_20261018/`）と同じ4曲・同じコマ列・同じ正解データを使い、
**変えるのは切り出し粒度だけ**にしてある。

結果の読み物＝`C:\Users\conan\hisho\research\比較_切り出し粒度_2026-10-29.md`

## 前提の訂正（この実験を作るときに分かったこと）

2026-10-18 の比較の入力は「帯」ではなく**技法別の数字窓**だった。
`ocr_compare_20261018/extract_rois.py` が `results_wao_<S>/<曲>/roi.json`（カウンターごとの枠）で
切った画像を保存しており、全候補はその窓だけを読んでいる。
したがって前回の条件は、この実験でいう**条件B**にあたる。

## 条件（切り出し粒度）

| 条件 | 入力 | 大きさ | 1コマあたりの画像 |
|---|---|---|---|
| A | 帯まるごと（加点表示領域の全体） | 2480×120 | 1枚（6つの数字が同時に写る） |
| B | 技法別の数字窓（2026-10-18 と同一） | 67×70〜90 | 6枚 |
| C | 固定ピッチの桁窓（桁数に関わらず2枠） | 33×47 ×2 | 12枚 |
| C2 | 桁ごとの窓（桁数を測ってから1枠または2枠） | 33×47 ×1〜2 | 6〜12枚 |

条件C・C2 の桁窓は `build_slots.py` が実測から決める（`work/slots.json`）。
`probe_align.py` の実測で、数字は窓の中で**中央揃え**（1桁と2桁で中心が一致・差0.0〜5.0px、
左端の差10〜21px・右端の差11〜20px）であることが分かっているため、
「桁位置が固定」という前提をそのまま実装した条件Cと、中央揃えを踏まえて直した条件C2 を分けている。

## ファイル

| ファイル | 役目 |
|---|---|
| `probe_geometry.py` | 数字の箱の分布を曲×技法ごとに実測する（桁位置が固定かの下調べ） |
| `probe_align.py` | 正解値で1桁・2桁に分け、左詰め／中央揃え／右詰めのどれかを判定する |
| `build_slots.py` | 桁窓の校正値（中心 cx・cy、ピッチ、窓の大きさ、桁数判定のしきい値）を決める |
| `extract_bands.py` | 条件A の入力（帯のコマ）を 2026-10-18 と同じコマ列で保存する |
| `gran_core.py` | 条件ごとの切り出しと割り当ての共通部品（帯の上での読み・桁窓の切り出し） |
| `run_gran.py` | 条件×手法を1つ指定して走らせ、予測と処理時間を書き出す |
| `run_all_gran.sh` | 仕事を4レーン（各専用4コア）に並べて走らせる |
| `score_gran.py` | 同じ尺度で採点し、比較表と「1が11に見える」型の誤りの件数を作る |
| `reproduce_check.py` | 条件B の再実行が 2026-10-18 と1件も違わないことを実測する |
| `make_figure_gran.py` | 比較表から図1枚（PNG）を作る |
| `glyph_core.py` | 読取器 v0.8e の参照実装（`ocr_compare_20261018/` からの写し・変更なし） |

## 再現手順

```bash
source ~/ocr_compare_20261018/env.sh
PY=~/ocr_compare_20261018/.venv312/bin/python

# 1) 桁位置の実測と桁窓の校正
$PY probe_geometry.py --out result
$PY probe_align.py   --out result
$PY build_slots.py   --out work

# 2) 条件A の入力（2026-10-18 と同じコマ列であることを自分で確認して止まる）
$PY extract_bands.py --out ~/ocr_gran_20261029/band

# 3) 条件×手法を全部走らせる（セッションから切り離す）
setsid nohup bash run_all_gran.sh > ~/ocr_gran_20261029/orchestrator.log 2>&1 < /dev/null &

# 4) 条件B の再現確認（2026-10-18 と1件も違わないこと）
$PY reproduce_check.py --new pred/_full

# 5) 採点
$PY score_gran.py --pred pred      --out result --sub 4 --tag sub4
$PY score_gran.py --pred pred/_full --out result --sub 1 --tag full

# 6) 図（Windows 側＝日本語フォントがある python で）
python make_figure_gran.py --result result --out result/fig_gran.png
```

## 間引きについて

全手法を同じ土俵で比べるため、主たる表は 2026-10-18 のコマ列をさらに4つに1つへ間引いた
**10,794件**（1,799コマ×6カウンター）で作る。
見本照合と生ピクセル最近傍だけは全件（43,170件）でも走らせ、`pred/_full/` に置く。
帯消失ガードの移動平均の半幅は間引きに合わせて `round(150/(8*sub))` 標本に換算する。
それ以外の後処理（6コマ安定・減らない制約）は 2026-10-18 と同一。

## 注意

- 正本（`read_counters*.py`）・正式結果（`results_wao_20261014`）・正解データ
  （`dataset/G1_events_20261014_wao.csv`）・2026-10-18 の実験一式は**読み取り専用**で参照する。
- 帯動画は可変フレームレートで `cv2` のシークがずれるため、コマの採取は必ず逐次デコードで行う。
- 条件A では v0.8e の「ごみ上限 1200」を外している。帯では背景のパネルそのものが閾値を超えて
  1つの大きな連結成分になり（実測＝T=200 で 38,472・T=170 で 63,166）、面積比で比例配分した
  上限を置くと数字が現れる低い閾値が全部弾かれるため。現行手法に最も有利な形にしてある。
